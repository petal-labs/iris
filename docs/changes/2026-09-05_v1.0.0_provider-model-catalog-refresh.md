## Summary

Adds 13 new models to the static provider catalogs in `providers/<name>/models.go`,
synced against the models.dev catalog (`https://models.dev/api.json`) as of
2026-09-05. New flagships land for OpenAI (`gpt-6-astra`), Anthropic
(`claude-fable-5-1`), Gemini (`gemini-3.8-flash`, `gemini-3.7-flash`), xAI
(`grok-4.6`) and Z.ai (`glm-5.3`, `glm-5.3-flash`). Also adds the generally
available ids for two Gemini image models and the Grok 4.20 family, which had
previously only been exposed under their preview/beta ids, plus the
`gemini-embedding-2` embedding model.

No existing model id, constant name, or constant value changes. This release is
purely additive to the exported surface.

## Motivation

Issue #123 asks Iris to track the latest models from its supported providers.
The catalogs are the SDK's source of truth for model discovery (`Provider.Models()`),
capability queries (`SupportsToolCalling`, `IsReasoningModel`, ...) and — on
OpenAI — endpoint routing, so a model absent from the catalog is invisible to
callers and, on OpenAI, silently routed to the wrong API.

The catalogs are deliberately curated rather than a mirror of models.dev: Iris
lists chat, reasoning and image flagships only, and excludes dated snapshots
(`claude-opus-4-5-20251101`, `gpt-4o-2024-08-06`), text-to-speech, video,
realtime and open-weight model families. This change keeps that curation.

## Technical Specification

### Data Schemas / Types

No type definitions changed. Every addition is a `core.ModelInfo` literal in an
existing `models []core.ModelInfo` slice:

```go
// core/types.go
type ModelInfo struct {
    ID           ModelID     `json:"id"`
    DisplayName  string      `json:"display_name"`
    Capabilities []Feature   `json:"capabilities"`
    APIEndpoint  APIEndpoint `json:"api_endpoint,omitempty"` // defaults to completions
}
```

Capabilities were derived from the models.dev fields `reasoning`, `tool_call`,
and `modalities.output`:

| models.dev field | Iris feature |
|---|---|
| `reasoning: true` | `core.FeatureReasoning` |
| `tool_call: true` | `core.FeatureToolCalling` |
| `structured_output: true` | `core.FeatureStructuredOutput` (OpenAI only — see note) |
| `modalities.output` contains `image` | `core.FeatureImageGeneration` |
| always, for chat models | `core.FeatureChat`, `core.FeatureChatStreaming` |

**Note on `FeatureStructuredOutput`:** only the OpenAI catalog uses this feature
today; the Gemini, xAI and Z.ai catalogs do not declare it on any entry, even
where models.dev reports `structured_output: true`. The new entries follow the
existing per-provider convention rather than introducing the feature to
providers that have never declared it, since `SupportsStructuredOutput` would
then report inconsistently across an otherwise uniform catalog.

**Naming contract for the Gemini image constants.** `ModelGemini3ProImage`
already existed and holds the *preview* id `"gemini-3-pro-image-preview"`.
Rather than repoint that exported constant at the GA id — which would silently
switch a pinned caller onto a different model — the GA id is exposed under the
new name `ModelGemini3ProImageStable`, and `ModelGemini3ProImage` keeps its
original value. A comment in `providers/gemini/models.go` records this.

The `gemini-3.1-flash-image` pair had no such collision: the preview constant
was already named `ModelGemini31FlashImagePreview`, so the GA id took the
unsuffixed `ModelGemini31FlashImage`.

## Usage Examples

### Example: calling the new OpenAI flagship

`gpt-6-astra` declares `APIEndpoint: core.APIEndpointResponses`, so
`shouldUseResponsesAPI` routes it to the Responses API rather than Chat
Completions. No caller-side change is required.

```go
package main

import (
    "context"
    "fmt"
    "os"

    "github.com/petal-labs/iris/core"
    "github.com/petal-labs/iris/providers/openai"
)

func main() {
    provider := openai.New(os.Getenv("OPENAI_API_KEY"))
    client := core.NewClient(provider)

    resp, err := client.Chat(openai.ModelGPT6Astra).
        User("Summarize the Go memory model in three sentences.").
        GetResponse(context.Background())
    if err != nil {
        fmt.Fprintln(os.Stderr, "Error:", err)
        os.Exit(1)
    }
    fmt.Println(resp.Output)
}
```

### Example: capability introspection for a new model

```go
info := xai.GetModelInfo(xai.ModelGrok420MultiAgent)
fmt.Println(info.DisplayName)                                   // Grok 4.20 Multi-Agent
fmt.Println(info.HasCapability(core.FeatureReasoning))          // true
fmt.Println(info.HasCapability(core.FeatureToolCalling))        // false
fmt.Println(info.GetAPIEndpoint())                              // completions
```

`grok-4.20-multi-agent-0309` is the one new entry that deliberately omits
`core.FeatureToolCalling`: models.dev reports `tool_call: false` for it. Callers
that gate on `HasCapability(core.FeatureToolCalling)` will therefore skip tool
wiring for this model instead of sending a request the API rejects.

Note that `GetModelInfo` is the one catalog accessor every provider exports. The
named convenience helpers (`SupportsToolCalling`, `IsReasoningModel`,
`IsEmbeddingModel`, ...) are exported only by `providers/azurefoundry`; the
other provider packages expose `GetModelInfo` alone. `HasCapability` is
therefore the portable form.

### Example: error case — an id that is still not in the catalog

Curated omissions (dated snapshots, TTS, video, realtime) remain unknown to the
SDK. `GetModelInfo` returns `nil` for them, and on OpenAI an unknown id falls
back to Chat Completions rather than erroring:

```go
info := openai.GetModelInfo("gpt-4o-2024-08-06")
fmt.Println(info == nil) // true — dated snapshots are not carried in the catalog

// Unknown ids are still sendable; they route to Chat Completions by default.
// Prefer the undated id (openai.ModelGPT4o) so capability queries work.
```

## Integration Notes

- **Catalogs are hand-maintained.** These edits belong in
  `providers/<name>/models.go`. The `cmd/gen-models` generator writes a separate
  `models_gen.go` that no provider reads; editing it has no effect on the SDK.
- **OpenAI routing is driven by the catalog.** `shouldUseResponsesAPI` calls
  `GetModelInfo(model)` and compares `GetAPIEndpoint()` to
  `core.APIEndpointResponses`. Omitting `APIEndpoint` on a new Responses-API
  model silently routes it to Chat Completions with no error — this is why
  `ModelGPT6Astra` sets the field explicitly and why a regression test now pins
  the behavior.
- **Gemini reasoning control.** `isGemini3Model` gates `thinkingLevel` (Gemini 3+)
  against `thinkingBudget` (Gemini 2.5). It matches on the `gemini-3` prefix, so
  `gemini-3.7-flash` and `gemini-3.8-flash` are covered with no code change.
- **Azure AI Foundry was intentionally left untouched.** Its
  `providers/azurefoundry/models.go` is documented in-file as a "representative"
  list of deployment names, uses raw string ids with no exported constants, and
  currently tops out at `gpt-4o` / `o1` with no GPT-5-era entries. Because Azure
  deployment names are chosen by the user at deployment time, that list is
  advisory rather than authoritative. Refreshing it is tracked separately.
- **Voyage AI has no upstream source.** models.dev does not carry a Voyage AI
  provider, so `providers/voyageai/models.go` cannot be synced from it and was
  left unchanged.
- **Perplexity was already current** — its four models (`sonar`, `sonar-pro`,
  `sonar-reasoning-pro`, `sonar-deep-research`) match models.dev exactly.

## Breaking Changes & Migration

None. No constant was renamed, no constant's value changed, no model was
removed, and no function signature changed. Existing code compiles and behaves
identically; the new ids are opt-in.

The Grok 4.20 beta ids (`grok-4.20-multi-agent-beta-0309`,
`grok-4.20-beta-0309-reasoning`, `grok-4.20-beta-0309-non-reasoning`) are now
marked in `docs/PROVIDERS.md` as superseded by their GA equivalents but remain
in the catalog and are still fully supported. Callers are encouraged, but not
required, to move to the GA ids:

```go
// before
xai.ModelGrok420BetaReasoning     // "grok-4.20-beta-0309-reasoning"
// after (recommended)
xai.ModelGrok420Reasoning         // "grok-4.20-0309-reasoning"
```

## Deferred / Out of Scope

The following upstream entries were reviewed and deliberately excluded:

- **Dated snapshots** — `claude-sonnet-4-5-20250929`, `claude-haiku-4-5-20251001`,
  `claude-opus-4-5-20251101`, `gpt-4o-2024-05-13/08-06/11-20`. Iris carries only
  undated ids.
- **`-chat-latest` aliases** — `gpt-5.2-chat-latest`, `gpt-5.3-chat-latest`, and
  the Gemini `gemini-flash-latest` / `gemini-flash-lite-latest` aliases. The
  catalogs list concrete API model names, not moving aliases.
- **OpenAI embeddings** — `text-embedding-3-large/-small`, `text-embedding-ada-002`.
  The OpenAI catalog has never carried embedding models.
- **Audio, TTS, video and realtime** — `gpt-realtime-2.1`,
  `gemini-2.5-flash-preview-tts`, `gemini-2.5-pro-preview-tts`,
  `gemini-3.1-flash-tts-preview`, `gemini-3.1-flash-live-preview`,
  `gemini-3.5-live-translate-preview`, `gemini-omni-flash-preview`,
  `lyria-3-*`, `veo-3.1-*`, `grok-imagine-video*`. Iris has no transport for
  these modalities.
- **xAI image generation** — `grok-imagine-image`, `grok-imagine-image-2.0`,
  `grok-imagine-image-quality`. The xAI provider exposes no image-generation
  path, so cataloging them would advertise an unreachable capability.
- **Open-weight families** — `gemma-4-26b-a4b-it`, `gemma-4-31b-it`.
- **Research and computer-use previews** — `deep-research-preview-04-2026`,
  `deep-research-max-preview-04-2026`, `gemini-2.5-computer-use-preview-10-2025`,
  `gemini-3.1-pro-preview-customtools`.
- **Azure AI Foundry catalog refresh** — see Integration Notes.
- **`examples/` directory Go programs** — the runnable examples still pin the
  previous flagships (`openai.ModelGPT56` in `examples/chat/responses-api`,
  `xai.ModelGrok45` in `xai-basic` and `xai-streaming`, `zai.ModelGLM52` in the
  three `zai-*` examples, `gemini.ModelGemini31FlashImagePreview` in
  `examples/image/gemini`). They compile and run correctly against those models;
  refreshing them is tracked separately, as it was for the previous catalog bump
  (see `2026-08-02_v0.17.0_example-model-refresh.md`). Note that
  `examples/chat/xai-reasoning` deliberately stays on `grok-3-mini`, the only
  Grok model that surfaces `reasoning_content` via `resp.Reasoning`.
