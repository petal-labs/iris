## Summary

Upgrades the default Anthropic API version from `2023-06-01` to `2026-10-21`
(`anthropic-version` header) and adapts request building to the breaking
changes that version introduces. Callers can still pin the old version with
`anthropic.WithVersion("2023-06-01")`.

## Motivation

Issue #137 asks Iris to upgrade to the latest Anthropic API version, following
the migration guide at
https://platform.claude.com/docs/en/api/migration-2026-10-21, and to identify
any breaking contract changes in Iris.

## Breaking contract changes identified

The `2026-10-21` changes that apply to raw HTTP requests to the Messages API
(and, transitively, token counting via `/v1/messages/count_tokens`):

1. **Sampling parameters are removed.** A request that sends `temperature`,
   `top_p`, or `top_k` is rejected with a 400 error, even at the default
   value. **This affects Iris**: the Anthropic provider forwarded
   `ChatBuilder.Temperature` as `temperature` in the request body. Iris never
   sends `top_p` or `top_k`, so `temperature` is the only affected field.
2. **Document blocks in assistant messages return a 400 error.** Iris does
   not send `document` blocks (its Anthropic mapping covers text, image, and
   tool blocks only), so no wire-format change was needed. The restriction is
   recorded here for completeness.
3. **Citations on `text` blocks in user messages return a 400 error.** Iris
   never sends `citations` on request blocks, so no change was needed.

Not applicable to Iris: the Admin/Analytics API field renames (no such
endpoints), the removal of the legacy Text Completions API (Iris only uses
the Messages API), the `betas` removal from non-beta Models methods (Iris does
not call the Models endpoints), and the SDK-level `MessageParam` union /
one-value-enum type changes (Iris is a raw HTTP client with its own types).

The change from `X-Api-Key` to `Authorization: Bearer <key>` is an SDK/CLI
behavior change, not an API contract change — "The Claude API accepts a key in
either header" — so Iris keeps sending `x-api-key`. Callers whose gateway
requires the key in `Authorization` can add it with `anthropic.WithHeader`.

## What Changed

- **`providers/anthropic/options.go`** — `DefaultVersion` is now
  `2026-10-21`. A new unexported constant `samplingParamsMinVersion` records
  the version that removed the sampling parameters.
- **`providers/anthropic/mapping.go`** — `buildRequest` takes the configured
  API version and only includes `temperature` when the version still accepts
  sampling parameters (`supportsSamplingParams`, a lexicographic date
  comparison: `2023-06-01` yes, `2026-10-21` no). This keeps temperature
  working for callers pinned to an older version while guaranteeing the
  current version never sends it. `providers/anthropic/client.go` and
  `providers/anthropic/streaming.go` pass `p.config.Version` through.
- **`docs/PROVIDERS.md`** — the Anthropic section documents the default API
  version, `WithVersion`, and the temperature behavior.

## Behavior Notes

- On the default version, `ChatBuilder.Temperature(0.7)` is silently omitted
  from the request body. Iris's established convention for parameters the
  provider cannot transmit is silent omission (providers have no access to
  the client's `WarningHandler`); the behavior is documented in
  `docs/PROVIDERS.md`.
- Sampling still behaves as before: a `2026-10-21` request without the
  parameters samples with their defaults, including `temperature` 1.0 — the
  same as a `2023-06-01` request that leaves them out.
- Streaming, token counting, tool use, and the Files API wire formats are
  unchanged by this migration.

## Integration Notes

- Callers relying on non-default `temperature` against Anthropic must either
  accept the default sampling behavior on `2026-10-21` or pin the provider:
  `anthropic.New(key, anthropic.WithVersion("2023-06-01"))`.
- No exported signatures changed: `DefaultVersion` keeps its name and type,
  and `buildRequest` is unexported.
- `go build ./...`, `go vet ./...`, `golangci-lint run`, and
  `go test ./...` pass (the `cli/keystore TestNewKeystoreLegacyMode` failure
  is pre-existing and environment-dependent).
