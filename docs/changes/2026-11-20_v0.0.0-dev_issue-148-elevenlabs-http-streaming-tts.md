## Summary

Implements HTTP streaming text-to-speech synthesis (`(*ElevenLabs).StreamSynthesize`)
via `POST /v1/text-to-speech/{voice_id}/stream` for Issue #148 (`IRIS-VOICE-005`).
Streams audio incrementally as isolated `core.AudioChunk` values over bounded
channels, enforces prompt cancellation and response body cleanup via
`context.AfterFunc` and `sync.Once`-guarded closing, propagates typed setup and
mid-stream errors, and enables `core.FeatureSpeechSynthesisStreaming` on
`ElevenLabs` and its verified TTS models.

## Motivation

Low-latency voice playback and downstream PetalFlow synthesis nodes (`#250`) need
audio chunks as soon as ElevenLabs generates them rather than buffering complete
utterances in memory. Bounded chunk and channel sizes keep memory O(chunkSize *
bufferSize) and prevent goroutine leaks when consumers cancel or abandon a stream.

## What Changed

### New Additions

- **`providers/elevenlabs/tts_stream.go`**:
  - `(*ElevenLabs).StreamSynthesize(ctx, req)` targeting
    `POST /v1/text-to-speech/{voice_id}/stream?output_format=...`:
    - Validates `req` and resolves `core.AudioFormat` and `model` before HTTP.
    - Streams incremental, non-aliased `core.AudioChunk` values with monotonic
      `Sequence` numbers over a bounded `Ch` channel, followed by a terminal
      `IsFinal: true` marker chunk and a `Final` `*core.SpeechResponse` carrying
      metadata (`ID`, `Model`, `VoiceID`, `Audio.Format`, `Usage.InputCharacters`,
      `Usage.OutputBytes`) with `Audio.Data` left empty to keep memory bounded.
    - Uses `context.AfterFunc` to close `resp.Body` immediately on context
      cancellation or provider timeout, unblocking pending reads and channel
      sends cleanly and closing `Ch`, `Err`, and `Final` without leaking
      goroutines.
    - Emits `core.ErrDecode` on empty 200 streams, `reqCtx.Err()` on
      cancellation/timeout, and `core.ErrNetwork` on mid-stream transport errors.
- **`providers/elevenlabs/tts_stream_test.go`**: Race-tested unit tests covering
  true incremental delivery (via `io.Pipe`), chunk buffer isolation, bounded
  channel capacity, `core.Client.StreamSynthesize` + `core.DrainSpeechStream`,
  cancellation during blocked `Read`, cancellation when consumer abandons a full
  bounded channel, mid-stream provider timeout, setup errors, empty streams, and
  mid-stream transport read failures.

### Modifications

- **`providers/elevenlabs/http.go`**: Made `cancelOnClose.Close()` idempotent

- **`providers/elevenlabs/doc.go`**: Documented HTTP streaming TTS, bounded

- **`providers/elevenlabs/provider_test.go`** & **`tts_test.go`**: Updated

### API Endpoints

- `POST {BaseURL}/v1/text-to-speech/{voice_id}/stream?output_format={format}`
  - Headers: `xi-api-key`, `Content-Type: application/json`
  - Request body: `{"text", "model_id", "language_code", "voice_settings", "seed", "previous_text", "next_text"}`
  - Response: chunked binary audio stream + `Content-Type`, `request-id`, `character-cost` headers
  - Errors: normalized via `normalizeError` on setup; mid-stream failures delivered on `SpeechStream.Err`.

## Usage Examples

### Example: Consuming Incremental Audio Chunks

```go
client := core.NewClient(provider)
stream, err := client.StreamSynthesize(ctx, &core.SpeechRequest{
	Model:   elevenlabs.ModelElevenFlashV25,
	VoiceID: "JBFqnCBsd6RMkjVDRZzb",
	Text:    "Streaming audio from Iris.",
	Format:  core.AudioFormatPCM16000,
})
if err != nil {
	return err
}

for chunk := range stream.Ch {
	if len(chunk.Data) > 0 {
		playAudioBytes(chunk.Data)
	}
}
if err := <-stream.Err; err != nil {
	return err
}
meta := <-stream.Final
```

### Example: Cancelling Mid-Stream (Error / Cleanup Case)

```go
ctx, cancel := context.WithCancel(context.Background())
stream, err := client.StreamSynthesize(ctx, req)
if err != nil {
	return err
}
cancel() // promptly closes HTTP body, emits context.Canceled on stream.Err, closes all channels
```
