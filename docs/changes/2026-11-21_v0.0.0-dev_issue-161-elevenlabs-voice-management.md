## Summary

Adds opt-in, authorization- and consent-gated voice library management and
instant voice cloning operations (`CreateVoice`, `EditVoice`,
`EditVoiceSettings`, `DeleteVoice`) to `providers/elevenlabs` for Issue #161
(`IRIS-VOICE-018`).

## Motivation

Applications that need programmatic voice management (updating voice settings,
editing owned voices, deleting obsolete clones, or creating instant voice
clones) require explicit opt-in activation, verifiable speaker consent,
pluggable RBAC/audit authorization, and strict upload/privacy safeguards so
existing read-only callers can never accidentally mutate voices or clone voices
without consent (FRD Architectural Decision 7).

## What Changed

### New Additions

- **`providers/elevenlabs/options.go`**:
  - Added `WithVoiceManagementEnabled()` (opt-in flag; defaults to `false` so
    all mutating voice APIs remain disabled unless explicitly enabled).
  - Added `WithVoiceAuthorizer(auth VoiceAuthorizer)` for pluggable RBAC,
    policy, or audit authorization checks before any mutating HTTP request.
- **`providers/elevenlabs/voice_management.go`**:
  - Sentinel errors: `ErrVoiceManagementDisabled` (wraps `core.ErrNotSupported`),
    `ErrVoiceConsentRequired`, and `ErrVoiceActionDenied`.
  - Authorization types: `VoiceAction` (`clone`, `edit`, `edit_settings`,
    `delete`), `VoiceAuthRequest`, `VoiceAuthorizer`, `VoiceAuthorizerFunc`.
  - Consent & sample types:
    - `VoiceConsent` (`Confirmed`, `SubjectID`, `GrantedBy`, `GrantedAt`,
      `EvidenceRef`) with `Validate()` (rejecting unconfirmed, missing fields,
      or future timestamps) and privacy-safe `String()`/`GoString()` omitting
      `SubjectID` and `EvidenceRef`.
    - `VoiceSample` (`Filename`, `Data` XOR `Reader`) with filename traversal
      sanitization (`..`, `/`, `\`, control chars) and privacy-safe formatting.
  - Endpoints:
    - `(*ElevenLabs).CreateVoice(ctx, *CreateVoiceRequest) (*CreateVoiceResponse, error)`
      (`POST /v1/voices/add` streaming multipart upload, requires confirmed
      `VoiceConsent`, 1..25 samples, bounded per-sample 10 MiB / total 50 MiB).
    - `(*ElevenLabs).EditVoice(ctx, *EditVoiceRequest) error`
      (`POST /v1/voices/{voice_id}/edit`, requires `VoiceConsent` whenever
      audio samples are uploaded).
    - `(*ElevenLabs).EditVoiceSettings(ctx, voiceID, *core.VoiceSettings) error`
      (`POST /v1/voices/{voice_id}/settings/edit`).
    - `(*ElevenLabs).DeleteVoice(ctx, voiceID) error`
      (`DELETE /v1/voices/{voice_id}`).
- **`providers/elevenlabs/voice_management_test.go`**:
  - Unit tests covering default-disabled guard (zero HTTP traffic), consent
    validation & PII redaction, authorizer denial, filename traversal & sample
    size caps (both in-memory and streaming `io.Reader`), happy-path multipart
    & JSON requests for all 4 operations, and context cancellation.

### Modifications

- **`providers/elevenlabs/voices.go`**, **`doc.go`**, **`docs/guides/speech.md`**, **`docs/PROVIDERS.md`**:
  - Documented the opt-in voice management API, consent/authorization
    safeguards, upload limits, and PVC limitations.

## API & Behavior

```go
provider, err := elevenlabs.NewFromEnv(
	elevenlabs.WithVoiceManagementEnabled(),
	elevenlabs.WithVoiceAuthorizer(authorizer),
)
created, err := provider.CreateVoice(ctx, &elevenlabs.CreateVoiceRequest{
	Name:    "Studio Host",
	Samples: []elevenlabs.VoiceSample{{Filename: "sample1.mp3", Data: data}},
	Consent: &elevenlabs.VoiceConsent{
		Confirmed: true,
		SubjectID: "opaque-speaker-id",
		GrantedBy: "self",
		GrantedAt: time.Now(),
	},
})
```

## Integration Notes

- Preserves 100% read-only behavior for all existing `elevenlabs.New` /
  `NewFromEnv` callers that do not pass `WithVoiceManagementEnabled()`.

## Breaking Changes & Migration

None. Existing read-only voice discovery and TTS/STT callers are unaffected.
