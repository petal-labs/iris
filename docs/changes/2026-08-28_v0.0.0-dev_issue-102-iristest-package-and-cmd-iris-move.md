## Summary

Issue #102 lands the two structural changes intentionally deferred from #78. The public SDK
test-utility package moves from `github.com/petal-labs/iris/testing` (package `testing`) to
`github.com/petal-labs/iris/iristest` (package `iristest`), and the CLI entrypoint moves from
`cli/cmd/iris` to the conventional `cmd/iris` alongside `cmd/gen-models`. Both are breaking path
changes with no behavioral change: the mock and recording provider APIs, the CLI flags, output, and
release artifact names are all identical.

## Motivation

The `testing` package name collided with Go's standard-library `testing` package. Any external test
that needed both had to alias one import, and the adjacent `testing/` (SDK doubles) and `tests/`
(repository suites) directories were easy to confuse. The collision was invisible inside the package
itself, because a Go package never resolves its own name in its own files — only downstream
consumers paid the cost.

The command tree was also split: `cmd/gen-models` used the conventional root `cmd/` location while
the user-facing CLI lived at `cli/cmd/iris`. That split leaked into the README install instructions,
the Makefile, the integration-test build, the development docs, and the release workflow.

The project is pre-1.0, which is the least disruptive window to establish durable package and
command paths.

## What Changed

### New Additions

- `github.com/petal-labs/iris/iristest` — package `iristest`, containing the SDK test doubles
  previously published as `github.com/petal-labs/iris/testing`. Files: `doc.go`,
  `mock_provider.go`, `mock_provider_test.go`, `recording_provider.go`, `recording_provider_test.go`.
- `cmd/iris/main.go` — the CLI `main` package, moved verbatim from `cli/cmd/iris/main.go`.

### Modifications

- Package declaration in every `iristest` file changed from `package testing` to `package iristest`.
- `iristest/doc.go` package comment and all its example snippets now use the `iristest` qualifier
  (`iristest.NewMockProvider`, `iristest.NewRecordingProvider`).
- `Makefile`: `build-cli` and `install-cli` build `./cmd/iris` instead of `./cli/cmd/iris`.

  ```make
  # Before
  go build $(LDFLAGS) -o bin/iris ./cli/cmd/iris
  go install $(LDFLAGS) ./cli/cmd/iris

  # After
  go build $(LDFLAGS) -o bin/iris ./cmd/iris
  go install $(LDFLAGS) ./cmd/iris
  ```

- `README.md`: install command changed from
  `go install github.com/petal-labs/iris/cli/cmd/iris@latest` to
  `go install github.com/petal-labs/iris/cmd/iris@latest`.
- `tests/integration/main_test.go`: `TestMain` builds the harness binary from `./cmd/iris`.
- `.github/workflows/release.yml`: all four cross-compilation steps (linux/amd64, darwin/amd64,
  darwin/arm64, windows/amd64) build `./cmd/iris`.
- `docs/DEVELOPMENT.md`: the repository-structure tree now shows `iristest/` and a root `cmd/` node
  containing `iris/` and `gen-models/`, with `cli/` described as the CLI implementation packages;
  the CLI build snippet and the import overview use the new paths.
- `docs/guides/testing.md`: import path, prose reference, and every snippet qualifier updated to
  `iristest`.
- `examples/testing/mock-provider/main.go`: import and qualifiers updated to `iristest`, with the
  import kept in sorted order within the module group.

### Removals

- `github.com/petal-labs/iris/testing` no longer exists. No forwarding or deprecation shim was
  added, because a shim would preserve the standard-library naming collision this change exists to
  remove.
- `cli/cmd/iris` (and the now-empty `cli/cmd`) no longer exist.

## Technical Specification

### Go Package API

The exported surface is byte-for-byte unchanged apart from the package clause. The following remain
available at the new import path with identical signatures and semantics:

```go
package iristest

// MockProvider: deterministic stand-in for core.Provider.
func NewMockProvider(responses ...core.ChatResponse) *MockProvider
func (m *MockProvider) WithID(id string) *MockProvider

func (m *MockProvider) WithFeatures(features ...core.Feature) *MockProvider
func (m *MockProvider) WithResponse(resp core.ChatResponse) *MockProvider
func (m *MockProvider) WithResponses(responses ...core.ChatResponse) *MockProvider
func (m *MockProvider) WithDefaultResponse(resp core.ChatResponse) *MockProvider
func (m *MockProvider) WithError(err error) *MockProvider
func (m *MockProvider) WithErrors(errs ...error) *MockProvider
func (m *MockProvider) WithStreamingResponse(chunks []string, final *core.ChatResponse) *MockProvider
func (m *MockProvider) WithStreamingError(chunks []string, err error) *MockProvider
func (m *MockProvider) ID() string
func (m *MockProvider) Models() []core.ModelInfo
func (m *MockProvider) Supports(f core.Feature) bool
func (m *MockProvider) Chat(ctx context.Context, req *core.ChatRequest) (*core.ChatResponse, error)

func (m *MockProvider) CallCount() int
func (m *MockProvider) LastCall() *MockCall
func (m *MockProvider) Reset()
func (m *MockProvider) ResetAll()

// RecordingProvider: wraps a real provider and records traffic.
func NewRecordingProvider(underlying core.Provider) *RecordingProvider
func (r *RecordingProvider) ID() string

func (r *RecordingProvider) Supports(f core.Feature) bool

func (r *RecordingProvider) LastRecording() *RecordedCall
func (r *RecordingProvider) Clear()

func (r *RecordingProvider) Underlying() core.Provider
```

The exported types `MockProvider`, `MockCall`, `RecordingProvider`, and `RecordedCall` keep their
field sets unchanged.

A bare `MockProvider` still advertises chat, streaming, tool calling, structured output, and web
search so chat-builder capability gates do not obstruct ordinary tests; the first `WithFeatures`
call replaces those defaults and later calls add to the customized set. `RecordingProvider` still
implements `core.ProviderUnwrapper`, so `core.AsEmbeddingProvider` and the other `core.As*` helpers
continue to see through it.

### CLI Interface

No CLI flags, subcommands, output formats, or artifact names changed. Only the package path used to
build the binary changed.

```bash
# Install from source
go install github.com/petal-labs/iris/cmd/iris@latest

# Build locally
make build-cli          # -> bin/iris
go build -o bin/iris ./cmd/iris
```

Version metadata is still injected into the `cli/commands` package, which did not move:

```bash
go build -ldflags "-X github.com/petal-labs/iris/cli/commands.Version=$VERSION \
  -X github.com/petal-labs/iris/cli/commands.Commit=$COMMIT \
  -X github.com/petal-labs/iris/cli/commands.BuildDate=$DATE" \
  -o bin/iris ./cmd/iris
```

## Usage Examples

### Example: migrating a downstream test to `iristest`

```go
// Before — the alias was mandatory whenever the file also used stdlib testing.
package myapp_test

import (
	"context"
	"testing"

	"github.com/petal-labs/iris/core"
	iristesting "github.com/petal-labs/iris/testing"
)

func TestGreeting(t *testing.T) {
	mock := iristesting.NewMockProvider(core.ChatResponse{Output: "Hello!"})
	client := core.NewClient(mock)

	resp, err := client.Chat("gpt-4o").User("Hi").GetResponse(context.Background())
	if err != nil {
		t.Fatalf("GetResponse: %v", err)
	}
	if resp.Output != "Hello!" {
		t.Errorf("Output = %q, want %q", resp.Output, "Hello!")
	}
}
```

```go
// After — no alias needed; the package name no longer collides.
package myapp_test

import (
	"context"
	"testing"

	"github.com/petal-labs/iris/core"
	"github.com/petal-labs/iris/iristest"
)

func TestGreeting(t *testing.T) {
	mock := iristest.NewMockProvider(core.ChatResponse{Output: "Hello!"})
	client := core.NewClient(mock)

	resp, err := client.Chat("gpt-4o").User("Hi").GetResponse(context.Background())
	if err != nil {
		t.Fatalf("GetResponse: %v", err)
	}
	if resp.Output != "Hello!" {
		t.Errorf("Output = %q, want %q", resp.Output, "Hello!")
	}
}
```

### Example: error case — building the old paths

```console
$ go build ./cli/cmd/iris
package github.com/petal-labs/iris/cli/cmd/iris: cannot find package

$ go install github.com/petal-labs/iris/cli/cmd/iris@latest
go: github.com/petal-labs/iris/cli/cmd/iris@latest: module github.com/petal-labs/iris@latest
	found, but does not contain package github.com/petal-labs/iris/cli/cmd/iris
```

Consumers still importing `github.com/petal-labs/iris/testing` will fail at compile time with a
missing-package error rather than silently resolving to a stale shim. That is deliberate: the break
is loud and the fix is a one-line import edit.

### Example: recording provider at the new path

```go
import (
	"github.com/petal-labs/iris/core"
	"github.com/petal-labs/iris/iristest"
	"github.com/petal-labs/iris/providers/openai"

recorder := iristest.NewRecordingProvider(openai.New(apiKey))
client := core.NewClient(recorder)

// ... exercise the code under test ...

for _, call := range recorder.Recordings() {
	fmt.Printf("model=%s messages=%d\n", call.Request.Model, len(call.Request.Messages))
}

// Optional capabilities still resolve through the wrapper.
embedder, ok := core.AsEmbeddingProvider(recorder)
```

## Integration Notes

- The reusable CLI packages `cli/commands`, `cli/config`, and `cli/keystore` deliberately stayed
  under `cli/`. Only the thin `main` package relocated. Because version strings are injected into
  `cli/commands`, the release workflow's `-ldflags` needed no change at all — moving the entrypoint
  was decoupled from version injection precisely because `main` holds no logic.
- `cmd/gen-models` is untouched; `cmd/` now holds both commands, which is the layout Go tooling and
  most Go consumers expect.
- The `examples/testing/` directory name is unchanged. It is an example *category* directory in a
  separate module, not an importable package path, so it carries none of the collision cost.
- One historical record, `docs/changes/2026-08-01_v0.17.0_issue-47-key-handling.md`, still contains
  the old package path inside a captured `go test` transcript, and
  `docs/changes/2026-08-28_v0.0.0-dev_issue-78-repository-hygiene.md` records the original deferral
  of the CLI move. Both are point-in-time records and were left as written.

## Breaking Changes & Migration

Two breaking path changes, both mechanical:

1. **Test-utility import path.** Replace `github.com/petal-labs/iris/testing` with
   `github.com/petal-labs/iris/iristest` and change the qualifier to `iristest`. If the import was
   aliased (commonly `iristesting`) to dodge the stdlib collision, the alias can be dropped.

   ```bash
   # Repository-wide migration
   grep -rl 'petal-labs/iris/testing' --include='*.go' . \
     | xargs sed -i '' 's|petal-labs/iris/testing|petal-labs/iris/iristest|g'
   gofmt -w .
   ```

   Aliased call sites still need their qualifier updated by hand, or the alias removed and
   `iristesting.` rewritten to `iristest.`.

2. **CLI source path.** Replace `github.com/petal-labs/iris/cli/cmd/iris` with
   `github.com/petal-labs/iris/cmd/iris` in install commands, build scripts, Dockerfiles, and CI
   configuration.

Already-installed `iris` binaries are unaffected; only future source builds and installs use the new
path.

## Deferred / Out of Scope

- Renaming the repository-only `tests/` suite directory.
- Moving reusable packages (`cli/commands`, `cli/config`, `cli/keystore`) out of `cli/`.
- Changing test-double APIs beyond the package rename.
- Changing CLI flags, configuration, output, or release artifact names.
- Renaming the `examples/testing/` example category directory.
- Providing a deprecated forwarding package at the old `testing` import path.
